## Specific checks requested

- **Snapshot uses the backup API.** Yes, `deps.db.backup(snapshotFile)`; the live `.db` is never copied. The journal-mode switch applies only to the snapshot copy.
- **Restore swap before DB open, rollback on every failure path.** Yes (see table). `rollBack` works from the files alone (if the staged DB is still in staging nothing was moved in), and the marker records the rollback directory before the first move. If `rollBack` itself throws, the marker stays, so the next start retries it.
- **Archive validation before any write outside staging.** Yes. Names, links, sizes, ratio and entry count are checked over the whole directory before extraction; the manifest schema and exact entry set before the first extraction; the schema version from the manifest and again from the staged DB (read-only) before anything is scheduled. Portable import uses the same preflight and reads attachments into memory with a per-file cap before any DB write.
- **Automatic backup and launch at login default off; real login items untouched.** Confirmed in code and tests. The automatic-backup folder only comes from the main-process folder dialog, and pruning removes only files matching the exact auto-name pattern.
- **Retention/GC.** `reconcileReferences` treats `note_attachments` (live and trashed notes, because the rows stay until purge), version `attachment_ids` and open drafts as references. A 7-day grace period applies, re-referencing resets the clock, rows are deleted in one IMMEDIATE transaction and files after commit, and GC skips while a portability operation runs (`isBusy`). Trash auto-purge defaults to never.
- **The five tests reworded for the size-limit message.** I read the full diff. Each change replaces one exact-string expectation with the new exact string (unit attachment-names.test, unit renderer/editor/uploader.test, integration attachments.test, integration ipc-handlers-phase03.test, e2e paste.spec). No matcher was loosened and no assertion was removed. The other removed test lines are catalogue updates: channel count 78→90 with the exact Phase 08 list asserted, token rows 13→15, runtime deps list, and `globalShortcut` now detected. The new capability test is stricter than the old one.
- **IPC.** 12 channels were appended, all zod-validated, main window only (stickies and the widget are refused per integration shortcuts.test › roles). Every path comes from a main-process dialog, and no renderer supplies a file path.

## Findings (non-blocking, assigned to Phase 09)

- **A08-F1 (low, UX): Enter in a brand-new note's title can be lost.** `NoteTitleInput` handles Enter with `editorRef.current?.commands.focus('start')`. If the editor has not mounted yet (Enter within moments of Ctrl+N), focus stays in the title, and the next typed text is appended to the title. dev-a11y-2.log recorded this: title `Keyboard noteTyped without a mouse`, empty body. In dev-debug-1/2 the problem went away when the test waited for either the editor or the saved title, which points at the editor-not-yet-mounted window. The test now waits for the saved title, which hides the race in the gate. There is no data loss: the text is visible in the title and can be edited. It needs typing faster than the editor mounts, so it is not a release blocker for this phase. Fix in Phase 09: when Enter arrives before the editor exists, record a pending "focus editor at start" and apply it when the editor is created, and add an E2E case that presses Enter immediately after typing the title, without the wait.
- **A08-F2 (low, housekeeping): staging left behind after a cancelled restore confirmation.** If the user prepares a restore and then cancels the confirmation, `data/restore-staging/` (one backup's size) stays until the next prepare. `openWithPendingRestore` returns early without a marker and does not remove it. Fix in Phase 09: remove the staging directory at startup when no marker exists, or when the confirmation is cancelled.
