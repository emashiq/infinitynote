# Release 0.2.0 progress

The v0.2.0 feature batch (CLAUDE.md, user decision 2026-10-10) runs in three implementation runs. This file records each run's plan and results.

## Run A plan (note view, tables, formatting, stickies)

Implementer: infinity-code-opus. Scope: application code for items 1-4 below; the website, brand assets and icons belong to another agent and are not touched.

1. Note view layout. The scroll container becomes the whole note pane (`.note-view` loses its centered 760 px column): the scrollbar sits at the pane's right edge and the text starts at the left with normal padding; lines use the available width. Banners, the save pill, the find bar and the reminder chip bar get the same horizontal padding as the text. The floating format bubble, slash menu and reminder chips stay inside the scrolling surface, so they keep scrolling with the text. Stickies keep their own padding.
2. Tables. `@tiptap/extension-table` 3.31.4 (pinned like the other Tiptap packages) in the shared schema (`src/shared/editor/`), so main's live-sync authority and every editor use the same nodes. `normalizeRichDoc` accepts `table > tableRow > tableCell|tableHeader > block+` with validated `colspan`, `rowspan`, `colwidth` and `align`; `table` gets a block ID, rows and cells do not, and the paragraphs inside cells keep theirs (a reminder or reference can target a cell's paragraph). Insert from "/" and the note menu through an "Insert table" dialog (rows, columns, header row; default 3 x 3 with a header row); a "Table" menu (bubble and note menu) adds and removes rows and columns, toggles the header row and deletes the table; Tab and Shift+Tab move between cells; columns resize by dragging. Plain text (search index, conversion, previews) reads a table as one line per row with tab-separated cells; Markdown export writes GFM tables. Clipboard: copying table content writes the HTML table and a tab-separated text version; pasting an HTML table (spreadsheets, web pages) or tab-separated text with several rows and columns creates a table. Paste stays sanitized.
3. Font and color formatting. `@tiptap/extension-text-style` 3.31.4: `TextStyle` with `Color`, `BackgroundColor` (the highlight), `FontFamily` and `FontSize`, each extended with validated parse and render rules: colors only as `#rrggbb` (hex and `rgb()` input normalized), font families only from a curated list stored as keys, sizes only from a fixed list. The same rules run in `normalizeRichDoc` (main) and in the paste sanitizer, which now rewrites inline styles to the allowlisted properties instead of dropping them, so no other CSS reaches a document. Readability: the presets are mid-tone colors with at least 3:1 against both editor backgrounds; "Default" removes the color so the text follows the theme; highlighted text without its own color gets dark or light ink from the highlight's luminance. Pasted pure black or white text and white or transparent backgrounds (document defaults) are dropped. The format bubble gains Font, Size, Text color and Highlight popovers (keyboard accessible, also in stickies). Markdown export and plain-text conversion drop these styles (documented as lossy).
4. Stickies. (a) Header: the title and the project label share one center line; the title keeps priority and the label truncates with a tooltip. (b) The window background follows the sticky color: main sets the BrowserWindow background on color changes and on theme changes, and the sticky page paints `html`/`body` in the sticky color. (c) The color popover keeps the six presets and adds a custom color (native color input plus a hex field); custom colors are stored as validated `#rrggbb` through `sticky:setColor` (the `notes.color` column is unconstrained TEXT, so no migration is needed for it). Header and text ink follow the background luminance. (d) Sticky text can be colored with the format bubble, and a per-sticky default text color (Automatic or a color) is stored in a new `notes.text_color` column (migration 008) through a new validated channel `sticky:setTextColor` and applies live.

Tests: unit (color helpers, text-style validation, schema normalization of tables and text styles, sanitizer style rewrite, TSV parse and serialize, plain text, Markdown, editor commands round trip), integration (migration 008, sticky service text color, IPC validation), targeted E2E (table insert, edit and copy/paste; formatting persisted after reload; scrollbar at the pane edge; sticky custom color and text color persisted; sticky header alignment). Gates: `npm run check` and the touched E2E specs only (fast mode).

## Run C plan (locked notes; full v0.2.0 gate)

Implementer: infinity-code-opus. Scope: locked notes (CLAUDE.md, v0.2.0 batch), then the full Windows gate for the whole batch (check, build, full E2E, package, packaged E2E). Website: only checked against the result, not edited.

1. Data (migration 010, D-111). `note_locks(note_id → notes ON DELETE CASCADE, kdf JSON, salt, password_key, os_key NULL, content BLOB, created_at, updated_at)`: the ciphertext and the wrapped keys live only here. `notes.locked` (0/1) is kept by triggers on `note_locks`, so every existing note query can tell a locked note without a join. A locked note's `content_json`, `content_text` and `plain_text` are empty; guard triggers abort any write that would put plaintext in a locked note's row, a version of it, a reminder source or a suggestion dismissal of it, or an unsealed draft. Any reader that does not know about locks sees an empty note (fail closed).
2. Crypto (main only, `src/main/locks/note-crypto.ts`). Random 256-bit data key per note; content AES-256-GCM with a random 96-bit IV per write and the note ID bound as additional data; the data key wrapped (AES-256-GCM) by a key derived from the password with scrypt (N = 2^17, r = 8, p = 1, 16-byte random salt; parameters stored per note for later migration). Wrong password = failed authentication tag, reported generically, with a growing delay after repeated failures (in memory). Keys are zeroed when dropped.
3. OS key (Windows Hello, D-113). An injectable verifier: on Windows a hidden `powershell.exe` (Windows PowerShell 5.1, `-EncodedCommand`, fixed script, no user strings, timeout) calls `UserConsentVerifier.CheckAvailabilityAsync` and, for unlock, `RequestVerificationForWindowAsync` with the main window handle (so the prompt is parented to the app and comes to the front), falling back to `RequestVerificationAsync`. The data key copy for Hello is protected by Electron `safeStorage` (DPAPI) and released only after `Verified`. Linux and Windows without Hello: unsupported, only Password is offered with the reason. A password is always required (never Hello-only).
4. Lock lifecycle (`LockService`). Lock: password twice in the UI plus the "cannot be recovered" acknowledgement (main requires `acknowledged: true`); optional Windows Hello (verified once at setup); a sticky is removed from stickies first (a locked note never floats). Main saves the live-sync session, derives the key, then in one synchronous step closes the session, encrypts and purges: versions, drafts, reminder sources, suggestion dismissals, the note's plain text (FTS row), then FTS `optimize`, `VACUUM` and `wal_checkpoint(TRUNCATE)` with `secure_delete` on, so freed pages and the WAL do not keep the text. The note is locked at once. Unlock (password or Hello) lasts for the session; re-lock after the idle setting (`locks.autoLockMinutes`, default 5; 1, 5, 15, 30, 60), on OS lock-screen and suspend, on quit, by "Lock now" and "Lock all notes". Re-lock saves and closes the session (views get `collab:reset`, rejoin and see the lock screen), then zeroes the key. Change password (current password; data key re-wrapped, content untouched), Windows Hello on or off (password), Remove lock (password; content back to plaintext from then on; history stays gone).
5. While locked (and unlocked for the session): saves write ciphertext only; no versions; conflict drafts sealed with the note key; no format conversion; no reminder suggestions or "reminder from text"; search, backlink context, the reference picker and previews see nothing (title stays visible and searchable, shown with a lock icon); reminder notifications say "Reminder in a locked note" instead of the reminder title; portable export skips locked notes (count reported); Markdown export needs the note unlocked; backups contain only ciphertext. Attachments and linked files are not encrypted (said in the lock dialog).
6. UI. Lock screen in the tab (password, Unlock, "Use Windows Hello" when set up, generic error, backoff message); lock dialog (two passwords, Windows Hello option or the reason it is not offered, what stays visible, attachments not encrypted, earlier backups keep the text, the acknowledgement); "Lock settings" dialog (Lock now, change password, Windows Hello, remove lock); note menu, Details panel "Lock" section, palette "Lock note…", "Lock note now", "Lock all notes"; lock icons in the tree, tabs, Home, search; Settings > Notes "Lock locked notes again after".
7. IPC (main window only; passwords only in requests, never logged or echoed): `lock:availability|status|set|unlock|unlockHello|lockNow|lockAll|changePassword|setHello|remove`; `NoteDto.locked`; tree:changed reason `lock`.

Tests: unit (crypto round trip, wrong password, tampered IV/tag/ciphertext/AAD, stored scrypt parameters; Hello adapter with a fake PowerShell runner: available, not configured, verified, canceled, timeout, garbage, unsupported platform; contracts, migration checksum); integration (migration 010 and guard triggers; purge on lock with every table and the FTS vocabulary empty for the note and a raw byte scan of the database and WAL after lock; unlock, edit, ciphertext on disk; re-lock by idle, power and quit; backoff; change password, Hello on/off with fakes, remove lock; drafts sealed; export skip; reminders notification masking; IPC validation and role); E2E (lock with password: body hidden in the tab, search and Home; unlock, edit, restart, still ciphertext on disk and readable after unlock; wrong password; Lock now; Windows Hello with the injected fake; remove lock; history empty after lock). Real Windows Hello is not exercised automatically.
