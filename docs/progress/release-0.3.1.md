## Plan

1. **Rename documents.** Reproduce in WSL first. Stickies share the editor. Short "Diagrams" section on website/docs.html and in the in-app shortcuts help.
3. **Dates in spreadsheets.** A date parser for d-m-yyyy, d/m/yyyy, d.m.yyyy, m/d/yyyy and yyyy-m-d (optional time) with the OS date order for ambiguous day/month; plugged into FortuneSheet's text-type detection through the existing build-time patch (no fork); a date number format that shows the date as typed; xlsx keeps serial + format; CSV writes the shown text and reads such text back as dates. 4. **Locked documents.** An extension of the lock service: the same key derivation and wrapping, vault session, idle/Lock now/Lock all/screen lock/suspend/quit rules, unlock screen and dialogs (made target-neutral). Migration 015 (`document_locks`, `documents.locked`, sealed blobs, plaintext guards). Locking seals the current bytes into a new blob, deletes plaintext versions and the indexed text, seals the document's comments, removes the old plaintext blob files at once (unless another item uses the same bytes) and scrubs the database. The document protocols decrypt in memory only while unlocked; saves, restores and new versions are sealed; search does not index locked documents; backups keep the ciphertext. Linked documents are offered "copy into Infinity Notes and lock" within the copy limit. Tree, tab and header show a lock; graph and links show the title only.

## Decisions

- **D-182 (rename).** Root cause of "cannot rename": the tree's context-menu "Rename" closed its input at once for every item (notes too): the menu returns the focus to the row in its unmount effect, which runs after the rename input mounted and focused, so the input's blur committed the unchanged name. Reproduced under Xvfb (`repro1.log`: input not shown after the menu's Rename, for xlsx, docx, pdf and a note). F2 on a row worked with every viewer open, and FortuneSheet's document-level handlers did not take the typing (`repro2.log`, `repro3.log`). Fix: a menu gives the focus back to its opener only when the focus is still in the menu or nowhere, so an item that moved the focus on purpose keeps it. Document tabs and the header had no rename at all; they now share the tree's rename input and check.
- **D-183 (finding diagrams).** One `insertDiagram` (starter flowchart) behind every entry: the note context menu's "Insert diagram" (after "Insert table…"), the slash menu, the palette ("Insert diagram", through a generalized note insert request that also carries "Link to note or document…"), and the formatting toolbar's Diagram toggle (empty line: starter; selected text or a code block: becomes the Mermaid source; a diagram: back to text). Enter after a fence line (```` ```lang ````, not mid-line, not where no code block may stand such as a list item's first line) makes a code block of that language; space already did through Tiptap's input rule. Pasted plain text with complete Markdown fences becomes paragraphs and code blocks (unclosed fences stay text); when the clipboard also has HTML without `pre`/`code`/`table` (VS Code copies styled lines), the text's fences win. Pasted HTML finds the language class on the `pre`, its first child or its `code` element. Stickies share the editor, so all of it works there. The title-bar menus list no note insert actions, so none was added there.

## Repair (acceptance B1, m1-m8)

### Changes

- **B1 (blocker), structural.** The vault no longer hands out its key buffer: `LockVault.keyOf` is gone; `withKey(id, use, message)` runs a synchronous use (an asynchronous one throws), `keyAccess(id)` gives ciphers a `KeyAccess` that resolves the key for each value, `requireUnlocked(id)` checks without using. `heldKey(buffer)` wraps a key a lock change owns. Callers moved: `DocumentLocks.sealerOf` (key taken when the bytes are sealed, after `putSealed`'s content check; a key gone by then is FORBIDDEN `lockedDuringSave`), `DocumentLocks.plaintextOf` (key taken after `store.read`; m4: a relock during a read is FORBIDDEN, so the lock screen shows, not "damaged"), `sealedComments` (KeyAccess per value; used by `comment-service.ts`, `note-content.ts`), the vault's own note content, draft and seal paths, `openDraft`, `lock-service.ts` remove. Audit of every key use (notes included: `note-crypto` takes keys as arguments and is synchronous; `collab-hub`, `draft-service`, `note-writer`, `note-reader`, `reminder-service`, `note-export` call vault methods that use the key synchronously; the lock operations' own data keys are their buffers, zeroed in `finally`): no other vault key is held across an await. A save refused this way keeps its edits in the tab (`DocumentController.heldEdits`: the banner "Edits made just before the document locked again were not saved" with **Save them** after unlocking and **Discard them**).
- **m1, m2.** One per-document queue for content changes (`KeyedQueue`, shared by DocumentService and DocumentLocks): saves, restores, `lock()`, `remove()` and relock's key drop run one at a time. A relock waits for a save under way (sealed with the real key); a plaintext save under way is sealed by the lock after it, so no plaintext blob is left behind; `remove()` also re-checks revision and blob (CONFLICT).
- **m3.** `document:saveCopy` is refused for a locked document (`noCopyInside`), and the conflict banner hides **Save a copy…** for one.
- **m5.** A locked document's comment anchors are sealed (`anchor_json` holds `{"type": "sealed", "data": ...}`, purpose `anchor`, bound to the thread), sealed on lock, opened on removal; migration 015's triggers refuse a plaintext anchor on a locked document (015 is unreleased, so it was amended; its checksum regenerated, 1-14 unchanged). Notes keep plain anchors (block IDs only).
- **m6.** Ctrl+Shift+V keeps Markdown fences as text: the paste props track Shift (as ProseMirror does) and skip the fenced-text branch.
- **m7.** The graph marks locked documents (`graph-repo`/`graph-service` read `locked`; locked color and lock icon for notes and documents).
- **m8.** The document protocol's comment on in-memory bytes is corrected (pooled Buffers, offset and length).
